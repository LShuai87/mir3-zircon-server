# 屏幕顶部怪物血条：暗黑 2 风格设计

日期：2026-11-07

状态：已按确认方案实现，包含后续确认的血量数值、百分比及按住快捷键临时查看。已完成离线回归与 SlimDX 绘制验证，尚未进行联机实战验收。
预览：[原始设计交互稿](monster-target-hud-preview.html)；[首版设计效果图](monster-target-hud-mockup.png)；[当前客户端控件实绘](monster-target-hud-client-preview.png)。前两项为最初设计示意，未包含后续数值选项；最后一项使用生产 SlimDX 控件与隔离测试数据绘制，不是联机游戏截图。

## 1. 推荐方案

将当前可以展开的怪物信息窗口，收敛为顶部居中的目标血条：**名称叠在暗红色血量上，首领下方只增加一行“首领”**。信息一眼读完，不需要展开、收起或查看属性。

风格取向是克制、厚重、暗色金属边框。按用户指定的暗黑 2 观感做适配设计，不承诺逐像素复刻。本轮外部检索没有返回可核验的官方界面图，因此预览是原创设计草案，不作为原作界面证据。

本方案针对屏幕上方的目标信息，沿用前一步已改为暗红色的怪物头顶血条。

## 3. 外观规格

```text
普通怪物
              ┌────────────────────────────────┐
              │████████ 骷髅战士 ███████░░░░░░░│
              └────────────────────────────────┘

首领
              ┌────────────────────────────────┐
              │████████ 赤月恶魔 ███████░░░░░░░│
              └────────────────────────────────┘
                             首领
```

以上字符仅表达默认结构；实际布局、文字及颜色见客户端控件实绘。

| 项目 | 规格 |
| --- | --- |
| 位置 | 游戏画面水平居中，外框顶端距画面顶边 24 px；以逻辑客户端尺寸计算 |
| 尺寸 | 普通怪与首领统一 360 × 32 px；详情行从 y=34 开始，高 18 px，总高 52 px |
| 安全边距 | 左右至少 24 px；可用宽不足时缩窄到 `min(360, viewportWidth - 48)`；宽度不足 72 px 时隐藏整个 HUD，避免纹饰与文字重叠 |
| 边框 | 复用 `data/Data/GameInter.Zl` 第 327 张（456 × 32 px）叶纹横框；左右各 24 px 原尺寸保留，中段截取到所需宽度，使用 `#B8A080` 压暗金色；血槽 x=15、y=8，宽为外框减 31 px、高 18 px，延伸至两端纹饰下方，填满框内开口，不留左右空隙 |
| 底槽 | 近黑色 `#17100F`，保证空血部分可识别 |
| 血量 | 暗红 `#8B0000`，从左向右填充；顶部 1 px 微弱红色高光 `#A52A22` |
| 名称 | 始终在整个血槽中央，不随填充宽度移动；暖白 `#E7DDCA`；16 px；黑色描边/阴影 |
| 首领名称 | 同样的布局，文字改暗金 `#D7BC80`；下方居中小字“首领”，12 px |
| 长名称 | 单行按实际字体测量后尾部省略，左右保留 24 px；不滚动、不闪烁、不撑大 HUD |
| 背景 | 仅血槽有底色，周围透明；不再有属性面板、标题栏和大块黑底 |
| 交互区域 | 整个 HUD 及文字、端帽均鼠标穿透，避免挡住移动或攻击 |

名称必须始终可读，血量降低不改变名称颜色。首领同时用文字和颜色表达，避免只靠颜色区分。

**主 HUD 默认只显示名称、血量形状与首领标识**。等级、攻击元素图标、攻防数值、八项抗性、展开与关闭按钮均已删除。

血量详情复用下方同一行，提供两个独立选项，默认均关闭：

| 游戏设置 | 配置键 | 示例 |
| --- | --- | --- |
| 顶部血量数值 | `MonsterBoxShowHealth` | `12,450 / 18,000` |
| 顶部血量百分比 | `MonsterBoxShowPercentage` | `69.2%` |

数值与百分比可单独显示，也可同时显示；首领组合示例为 **首领 · 12,450 / 18,000 · 69.2%**。默认按住 **H** 临时显示两项，松开后恢复配置；在“游戏 → 按键绑定 → Functions → 按住显示怪物血量详情”中修改。输入聊天、打开设置或模态窗口、客户端失焦、断线时清除临时按住状态，防止详情卡住。

数值使用千位分隔，百分比保留一位小数。正血量不足 0.1% 时显示 **<0.1%**；尚未满血时最多显示 99.9%，满血显示 100.0%。缺失或无效血量数据时隐藏 HUD，禁止编造数值。

首版不增加血量拖尾、抖动、发光、掉血数字动画或血条长度随怪物类别变化。让血条直接反映最新服务器数据，减少干扰和状态复杂度。

## 4. 显示与隐藏规则

本次简化重点是展示和面板状态，不改变攻击目标选择。HUD 选择器只读取目标对象，不写入 `TargetObject`、`MagicObject` 或战斗焦点。

### 有效目标

- `MonsterObject`，对象仍存在于当前地图且 `Visible=true`。
- `CompanionObject == null`，`PetOwner` 为空，`MonsterInfo.AI >= 0`：该 HUD 专用于野怪，宠物、伙伴、守卫不进入顶部敌人血条。
- 对象与现有数据均未标记死亡，且已知血量不为 0。
- `DataDictionary` 对应对象存在、`MaxHealth > 0`。首次数据未到时暂不显示，绝不假造满血。

排除 `PetOwner` 是本设计新增的展示筛选，不是当前代码已存在的行为；不改变召唤物攻击逻辑或宠物头顶血条。

### 目标优先级

1. 有效的鼠标指向怪物，临时展示其血量。
2. 否则回到有效的已点击焦点怪物 `FocusObject`。
3. 都无效时隐藏，清掉 HUD 展示引用，不保留上一个怪物。

| 场景 | 预期行为 |
| --- | --- |
| 鼠标指向普通怪 | 显示名称与暗红血条 |
| 点击 A 后移开鼠标 | 继续显示 A |
| 焦点为 A，临时指向 B | 显示 B；移开后回到仍有效的 A |
| 快速从 A 指向 B | 本帧切换名称、首领标识与血量；不让 A 的血量沿用到 B |
| 指向玩家、NPC、宠物或地面 | 回退到有效焦点；没有焦点则隐藏 |
| 当前目标死亡 | 若还有其他有效候选则切到该候选，否则立即隐藏；不展示尸体血条 |
| 对象移除、切地图、断线、场景销毁 | 清空展示引用和旧数据，隐藏 HUD |
| 最大血量变更 | 按新上限重新计算血量比例 |
| 血量数据缺失或上限无效 | 尝试下一候选；没有可用候选则隐藏；数据恢复后按当前候选重新显示 |
| 点击空地清掉焦点 | 当前仍指向有效怪则按指向显示，否则隐藏 |
| Esc | 取消本次 HUD 展示并暂时抑制当前同一指向/焦点组合；移到空地再指回、新目标或再次点击后恢复。抑制不改攻击目标 |
| 关闭“显示怪物信息” | 保持隐藏；重新打开后按当前候选刷新 |

Esc 的抑制只记一次输入状态，不设持久开关。否则简单执行 `Monster=null` 会被下一帧的鼠标/焦点重新赋值，表现为“关不掉”。

血量计算统一为 `clamp(Health / (float)MaxHealth, 0, 1)`；存活且血量大于 0 时至少保留 1 px 填充，避免很低的正血量因整数裁剪看起来已空血。

## 5. 配置与已有窗口位置

保留 `Config.MonsterBoxVisible` 的配置键和“显示怪物信息”设置入口，控制整个新 HUD。头顶血条的 `ShowMonsterHealth` 仍独立工作。

新 HUD 没有展开态，不读取或写入 `MonsterBoxExpanded`；遗留配置可保留，首版无需迁移或删文件。

新 HUD 固定顶部锚点，不接受旧 `WindowType.MonsterBox` 的位置和大小恢复。切换分辨率时重新计算中心位置。既有窗口记录保留即可，无需改用户数据库。

## 6. 实现范围

已在以下范围实现：

1. **`MonsterDialog.cs`**：保留 `Monster`、`RefreshHealth()`、`RefreshStats()` 的现有对接入口；删去旧属性区和展开交互，重新绘制血槽、名称和首领行。内部统一刷新空值与有效性。`RefreshStats()` 只更新新 HUD 所需内容。
2. **`GameScene.cs`**：统一目标候选和无目标清空规则；处理顶部锚点与 Esc 抑制。仅影响顶部 HUD，不改地图攻击逻辑。
3. **`CConnection.cs`**：复查数据移除、死亡、切图、断线的现有入口；现有入口足够的沿用，存在残留路径的补清理。
4. **窗口基类衔接**：保留 `MonsterDialog` 类名，改为轻量 `DXControl`，所有子控件均不可交互，不加入 `DXWindow.Windows`，因此不再恢复旧窗口位置。
5. **设置及快捷键**：在 `Config`、`DXConfigWindow` 中加入两个开关；在枚举末尾追加 `MonsterHealthDetails`，使用原按键绑定及自动补齐机制，默认 H。
6. **`MonsterHudState.cs`**：集中处理 HUD 的目标抑制、按住状态、血量填充和详情文本，供生产代码与独立回归使用。

血槽继续使用可控的暗红纯色填充，边框复用当前客户端 `GameInter #327` 叶纹素材。素材中央透明，适合覆盖在独立血槽外；左右端饰保持原比例，只有均匀的中段被截取，避免整体拉伸导致纹饰变形。装饰使用共享 `CEnvir.LibraryList` 缓存，复用引擎的按需加载与纹理缓存，不逐帧打开资源文件或创建纹理；素材缺失或尺寸不符时跳过装饰，血槽和详情照常显示。无需导入暗黑 2 原版资源，无需新增资源包、协议、服务端字段或数据库修改。

实现时不按帧创建字体、纹理或控件；只在目标、名称、血量、可见性或尺寸变化时使 HUD 绘制失效。

## 7. 验收清单

- 普通怪与首领均顶部居中，血量为暗红色；只显示本设计规定的信息。
- 名称在满血、半血、低血时位置稳定、清楚可读；超长名称省略后仍不越界。
- 鼠标指向优先、焦点回退、死亡/离场清理无残留；缺失数据不显示伪造血量。
- A/B 快速切换不串名称、血量或首领标识。
- Esc 不会下一帧重新弹出；新指向或新点击可以恢复显示。
- HUD 区域点击穿透；不改变攻击、追击、施法或选中目标。
- 小窗口和分辨率切换布局正确，旧窗口位置不能覆盖锚点。
- `MonsterBoxVisible` 控制新 HUD；宠物头顶黄色血条及普通怪头顶暗红血条保持当前效果。
- 客户端 Debug 编译通过，并在真实客户端战斗中验证。HTML 预览只能验证设计方向，不能证明 SlimDX 的最终效果。
