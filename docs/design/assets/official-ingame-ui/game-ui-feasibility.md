## 结论与范围

可以使用指定正式版安装目录中的素材，改造当前客户端登录后的游戏界面。范围为角色、包裹、小地图框、下方血量/魔法与快捷栏、聊天区域、功能按钮，以及 NPC 对话和相关交互卡片。此评估不将登录、选角、启动器等页面纳入实施范围。

这是客户端 UI 适配工作。不能把正式版文件直接覆盖当前资源库，也不能从图片资源自动得到完整窗口行为。核心素材能够解码已经实际验证；所有窗口的最终运行效果尚未验证。

## 角色面板布局与数据映射

角色面板需要按目标样式重建布局，工作范围包含装备栏位置、人物预览、属性分区及标签页。仅替换底图无法完成适配。

现有证据：CharacterDialog.cs:44 构造角色/状态/修炼三个标签页；126 行创建装备控件数组；各控件绑定 GameScene.Game.Equipment，并用 EquipmentSlot 标识实际槽位。Globals.cs:381 的 EquipmentSize 为 16。人物绘制在 CharacterDialog.cs:1664，当前基准点为 (130,270)；属性在 1897 行 UpdateStats 中按 Stat 枚举从当前角色读取。CConnection.cs 和 DXItemCell.cs 多处直接访问 CharacterBox.Grid，改造必须保持该映射可用。

实施建议：

1. 用独立布局定义记录新底图、窗口尺寸、人物锚点、每个 EquipmentSlot 的可见位置/尺寸，以及属性字段的位置和格式。当前武器槽在 (95,60)、衣服在 (135,60)，这些是控件坐标，不是物品数据标识，可以重排。
2. 装备仍按 EquipmentSlot 绑定。把武器控件移到新位置时，其 ItemGrid 和 Slot 不变，拖放、双击、提示和网络回包仍识别原来的武器槽。需同步重设可点击区域，避免图像和交互错位。
3. 将当前基础属性映射到新布局的显示区域，保留 Stat 含义及现有格式化规则。底图不提供字段的准确名称、语义及动态数据，需要对照正式版运行界面确认。不要按显示行号猜测属性，也不要为了对齐界面改变服务端计算。
4. 逐一核对当前 16 个装备槽与目标布局。若目标没有可确认的一一对应位置，建议增加同风格的扩展装备区或标签页，避免丢失入口；额外属性和修炼操作同样应有完整入口。这是兼容设计建议，不是已确认的正式版布局。
5. 第一阶段可在角色面板初始化时直接采用新布局。如果另外要求新旧样式可选，再对同一套控件应用两份布局，处理选中物品、窗口边界及重绘；样式切换不需要复制角色数据。当前尚未实现布局配置或样式切换功能。

验收以槽位语义和数据显示均正确为准：所有实际可用装备槽仍可访问、穿脱和回包刷新正确；人物预览的坐标、层级与特效正确；基础/扩展属性更新正确；修炼功能仍可使用。正式版布局的准确槽位和属性顺序需要运行画面对照后定稿。

## 推荐实施方式

1. 将所需正式版图片离线导出，保留原索引、尺寸、偏移，转换为独立的客户端 UI 资源库。当前 Library/Libraries.cs:13 与 Client/Models/MirLibrary.cs:34 使用 Zl；MirLibrary.cs:567 使用 DXT1 纹理。ImageManager/IMain.cs:64 的现有转换器处理 WTL，另有 BMP + Placements.txt 的构建入口，尚无 MIX/MIZ 导入入口。
2. 在游戏界面增加集中管理的素材映射、窗口尺寸、锚点和透明规则，避免直接替换原库导致既有索引含义冲突。
3. 先完成下方 HUD、按钮、快捷栏、聊天和小地图的整体布局，再完成角色/包裹窗口和 NPC 对话、交易、任务及服务卡片，统一窗口层级、快捷键和分辨率适配。GameScene.cs:705 等位置的默认布局也需要同步调整。
4. 保持现有服务器协议和业务数据作为第一阶段的约束。若后续要求增加正式版独有功能、装备槽或物品容量，应单独评估服务器改动。
