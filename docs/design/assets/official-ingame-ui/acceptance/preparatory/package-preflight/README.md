# UI 资源包预检与所有权准备

本批以用户确认的1024×768布局基准继续实施。已有截图直接复用；本组件不修改布局、分辨率或显示设置。

## 实现

- 编译目录使用不可变的包SHA256、语义ID、槽位、逻辑尺寸、有符号偏移和逐帧数据SHA256；必需ID与实际帧必须完全相等，拒绝重复或未绑定帧。运行时不读取JSON。
- 在调用原生MirLibrary前，限制包体64MiB、槽位65536、有效帧4096、单边4096；验证25字节帧头、严格0/1存在标记、DXT1补齐长度和连续数据区。拒绝越界、重叠、乱序、尾随数据以及影子/叠加层。
- Verify仅返回持有只读文件锁的CPU校验结果；此时Library不可访问。UploadAllFrames通过原生D3D9上传全部帧后，Library才可用。TryLoad在可处理的预检故障时返回false、空资源对象及诊断，供启动流程选择Legacy。
- 同一只读文件锁持续到所有使用者释放资源包；Windows在此期间拒绝写入、删除与覆盖这个文件。调用者必须在创建场景前预检，在所属渲染线程使用，并在控件不再引用资源后Dispose。
- 原生MirLibrary.Dispose不主动释放纹理。因此本所有权对象显式调用每帧DisposeTexture，再释放库与文件锁。失败时同样释放已上传的前序帧；不修改共享MirLibrary的现有行为。

代码见[预检实现](../../../../../../../Client/Envir/GameUiPackagePreflight.cs)、[独立用例](../../../../../../../tests/game-ui/OfficialUiPackagePreflightTests.cs)和[运行脚本](../../../../../../../tests/Run-GameUiPackagePreflightTests.ps1)。

## 验证结果

- 418项检查通过，其中288项为3次资源包生命周期内的真实D3D9纹理像素比对；使用现有ImageManager/Mir3Library.cs写入合成Zl，并由原生客户端读取。
- 覆盖坏哈希、缺包、非法头长/槽位/标记、缺帧/未绑定帧、错误尺寸/负偏移、13字节辅助字段、数据区重叠/间隙/截断/尾随、超预算、发布前访问、跨线程释放和文件锁。
- 覆盖完整上传、重复上传、缓存到期释放/重传、逐帧纹理失效/重传和重复Dispose。第二帧上传故障通过校验后反射破坏测试描述符注入，验证前序纹理与文件锁全部清理；生产接口不提供此故障注入能力。
- 缺包、错包哈希、损坏头及设备未就绪的TryLoad结果均为false，输出资源为null，文件锁释放；普通皮肤60项、控件/读取26项回归通过。Debug/Release构建通过。
