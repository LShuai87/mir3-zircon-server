# NPC 正文选项定位耗时与 CRLF 缓存修正

按既定 1024×768 窗口参考继续实施。NPC 主卡、选项、二级服务及确认弹窗保留原生样式；本轮只修改 OfficialV1 正文的选项定位与段落高度测量。

## 原因与实现

80 行正文的选项位于文末，但总字符数不足 4,096。旧逻辑只对更长的前缀使用段落定位，因此每个选项都按词反复测量前面的整段正文。基线分段计时显示，两次场景的选项重排分别耗时 3,053 / 3,038 毫秒，缓存视口和窗口组合布局均低于毫秒计时精度。

OfficialV1 现在从选项所在段落开始测量，并使用已有正文布局缓存补回纵向位置。保留原生词组测量、标签、事件、ID 和点击间隔；Legacy 的调用路径保持原有行为。

新增原生完整正文解析对照时发现 CRLF 边界：按 LF 分段后，单独测量保留下来的 CR 会多算一行，使后续选项偏移 13 像素。测量时去掉组成 CRLF 的末尾 CR，原始正文、字符索引和渲染输入保持完整。两个失败运行均保留，包括首次差异和补充坐标诊断后的同一差异。

## 验证结果

- 同一台测试机、同样 30 个 80 行合成响应：修正前 2,903–3,236 毫秒，平均 3,037.9 毫秒；修正后 1–52 毫秒，平均 5.4 毫秒。两次单独选项重排均为 1 毫秒。完整样本见 latency-comparison.json。
- NPC 24,071 项检查通过：3 个真实场景构造、773 次坐标命中、146 帧渲染、75 次设备重置，原生卡片 2,399,935 个像素一致。
- 五组样本覆盖首段、普通换行、80 行且不足 4,096 字符的正文、连续空行/CRLF/中英文混排，以及前段自动换行/同段前缀；两次 Official 场景共 40 个选项区域与原生完整正文解析的文字、尺寸和坐标一致。共 24 次正文纹理与独立完整正文绘制逐像素一致。
- 窗口集成 165,921 项、完整场景 180 项、Python 172 项及最终 Debug/Release 构建通过；清单绑定当前可执行文件和原 94 帧候选包。命令、哈希和完整覆盖以 verification.json 为准。
