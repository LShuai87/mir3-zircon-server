# 登录后 UI 部署与版本校验验证

验证日期：2026-11-08。适配基准：1024×768、窗口模式。本记录为 UI-26 的准备实现；UI-07/UI-12、五项 G0 和最终游戏验收尚未完成。实际客户端 RuntimeReady=false，Legacy 仍是默认值。

## 实施内容

- [清单生成器](../../../../../../build/game-ui/New-GameUiReleaseManifest.ps1)读取实际客户端的编译目录并执行同一 EXE 的 CPU 包预检，记录 EXE、全部同目录 DLL、可选 Zircon.exe.config、Zl 的长度及 SHA256；buildId 同时绑定帧、按钮四态及染色契约。
- [部署入口](../../../../../../build/Setup-ClientAssets.ps1)新增 GameUiStyle 和 ReleaseManifestPath。OfficialV1 先核对全部目标，再递归复制资源；原有 Legacy 命令继续可用。EXE、DLL、INI 和数据库保持原有保留规则。
- 部署期间持有清单、源包和目标程序文件的只读文件句柄，复制后再核对包哈希并原子更新目标清单。拒绝源/目标互相包含、目标互相包含、目录联接及符号链接。
- 部署脚本不更改客户端样式配置。实际编译目录未就绪时，伪造清单也不能放行。正式版安装目录未写入。

命令与暂存目录要求见[构建说明第14节](../../../../../build-and-debug.md#14-登录后-ui-部署清单与版本校验2026-11-08)。部署要求 Windows 内置 x86 Windows PowerShell；无需编译器或 Python。

| 实际客户端 buildId | 两个环境相同 | 两个环境相同 |

[PowerShell 7 结果](powershell7/results.json)与[Windows PowerShell 结果](windows-powershell/results.json)包含逐项结论。实际客户端清单内容相同；JSON 空白格式不作跨版本一致性要求，同一环境的重复生成要求逐字节相同。

成功部署使用临时目录中编译的测试宿主，仅该夹具把准备就绪值设为 true；其目录和 CPU 预检来自实际源码，GPU 入口不可用。真实客户端只验证清单生成、包一致性及未就绪拒绝路径。测试不启动游戏、不连接服务器、不读取玩家数据库。

覆盖：缺少清单/包、截断包、同长度损坏包、EXE/DLL 错版、错误 buildId、伪造资源契约、依赖缺项/重复/路径越界、多目标预检、目录包含、重复部署、递归 Zl 和现有设置/数据库保留。源码与日志哈希见 verification.json。

## 未完成项

- 整目录资源复制不是原子升级；磁盘等错误仍可能留下部分资产，需要停止启动后重新部署完整匹配包。未验收旧整包回退。
