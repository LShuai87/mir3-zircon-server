# 正式版聊天保存、加载与场景恢复验证

基准沿用用户确认的 **1024×768 窗口模式**，复用已有截图；截图文件的像素尺寸单独记录。游戏设置页、NPC 卡片和按钮后的确认弹窗保留原样式。

## 已接入行为

- 正式版“保存所有”从真实聊天组和原生标签捕获数据，写入配置目录的 `GameUiChat.OfficialV1.json`；Legacy 保留原生数据库保存入口。失败返回 false，按钮显示失败消息，原文件不变。
- 按原生标签按钮顺序保存名称、12 位筛选/透明/提醒标志、选中页、稳定组标识、主组/浮动状态及几何；六档分辨率分别保留。保存期间标签正在拖动或更新时拒绝写入。
- 正式版适配器安装完成后，按当前分辨率恢复已保存的原生标签；明确点击“重新加载所有”也使用此入口。没有匹配记录或文档损坏时，保留原生启动/加载行为，不改写 JSON。
- 普通分辨率切换仅在组标识、标签数量和名称顺序匹配时恢复几何；不重建标签，不重放筛选与选中状态。原消息历史、编辑器实例、HWND、草稿及选择范围保留。拓扑变化时使用当前布局与边界约束。
- 显式空布局进入场景后仍为空；合法的“无选中页”状态经恢复、绘制和再次保存后仍保留，原生标签点击可重新选中。
- 恢复中途异常沿用场景失败处理：停止正式版 UI 操作、保留资源引用直到场景释放，并要求重启。

## 缺陷修复

多标签删除测试复现了原生删除回调的空引用：筛选面板先于标签释放，而标签释放时会触发选中页切换/布局刷新。已把面板释放延后到标签释放完成；样式和业务事件保持原入口。增加失败原始异常输出，避免资源清理异常遮盖首个错误。

最初测试直接访问受保护的 Controls 字段，导致一次编译失败；之后两次运行保留了上述真实缺陷的失败日志。已修复并重新执行，不把这些失败计入通过结果。
