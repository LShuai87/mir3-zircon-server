# NPC、服务与辅助窗口的安全区组合布局

按既定 1024×768 窗口参考实施，NPC 主卡、二级服务和确认弹窗保留原生样式。本轮集中处理多窗口位置与层级。

- OfficialV1 在响应完成后统一求解 NPC、可见仓库、包裹及服务窗口；优先完整并排，空间不足时允许正文区域叠放，保留底层标题和关闭条。服务操作区在组合最前，全部窗口边界限制在 HUD 上方。
- 不改变任何服务或网格尺寸，不打开服务，不重建选项，不发送布局报文；隐藏成员不移动。计算成功后在禁止布局持久化写入的批次内提交位置。
- 包裹/仓库显隐在原生置顶完成后触发重排；布局后重算当前鼠标目标。原生模态窗口与物品/技能提示根保留在服务层上方。
- 分辨率变化复用同一入口；布局安装、卸载和回滚管理新增事件订阅。

## 验证与边界

本轮 NPC 检查 23,821 项，包含 3 个实际场景、763 次坐标命中、126 帧渲染及 75 次设备重置；原生卡片 2,399,935 个像素对比一致。窗口集成 165,921 项、完整场景 180 项、Python 172 项及 Debug/Release 构建通过。完整命令和证据以 verification.json 为准。NPC 回归覆盖 15 种响应、六分辨率、辅助窗口隐藏/重开、长正文和再次进入场景；部分组合执行实际 D3D 重置，并检查原生确认弹窗层级和鼠标静止时的命中刷新。另执行窗口集成、完整场景、Python 检查及 Debug/Release 构建。

早期失败日志全部保留：受保护成员访问造成测试编译失败；原有单卡外观对比受到前一场景辅助窗口遮挡，修正测试隔离时也发现原生测试存在后续状态依赖；包裹/仓库重新显示后的原生置顶顺序覆盖组合顺序，改为置顶完成后重排。仅增加鼠标刷新未修复层级失败，相关失败记录亦保留。新增组合设备重置后的一次截图还返回 D3DERR_DEVICELOST；保留失败日志，并增加每次重置后的实际渲染/截图验证。最终通过不能证明已覆盖所有真实设备丢失与恢复边界。

正文叠放时可通过标题区域切换前景，不能把“完整窗口位于安全区”解释为所有窗口正文同时无遮挡。独立任务窗口的打开回调、任务与所有服务的同时组合、用户手动切换前景后的全量命中、17 窗口生命周期、真实服务器存取、跨行选项最终视觉及目标硬件性能仍待验收；本轮不关闭这些项目。

30 个 80 行正文合成响应的端到端耗时为 2,902–3,328 毫秒，尚未定位耗时来源。测试的 5,000 毫秒上限仅用于识别测试卡死，不代表交互性能合格；性能验收继续保持待完成。
