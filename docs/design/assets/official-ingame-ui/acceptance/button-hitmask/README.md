# 主界面按钮透明命中准备

参考仍采用用户确认的1024×768窗口模式及既有截图，不要求重复采图。本次为命令轮盘后续布局提供可验证的输入能力：8个图像按钮按普通态的透明遮罩命中，透明边角可穿透；中性“栏”按钮和两个模式文字保留现有矩形命中。按钮位置、尺寸、原控件、事件、数据和发包处理不变。

新增GameUiButtonHitMask从BC1块解出逻辑尺寸内的二值透明度，正确区分透明选择子3与不透明黑色选择子0/1/2，拒绝损坏长度、空尺寸和填充区坐标。遮罩在绑定时一次读取为不可变CPU数据，读取后恢复资源流位置；鼠标移动不读文件、不上传纹理，也不依赖GPU指针。普通/悬停/按下/禁用共用普通态轮廓，实际候选包四态透明度一致。DXButton仅通过显式参数启用，默认保持原有命中规则；重新绑定Legacy及HUD事务回退恢复原设置。

[命中示意](current-button-masks.png)以3倍最近邻展示现有7个轮盘图像的矩形边界和实际有效轮廓，颜色仅用于诊断。[独立参考研究](reference-overlap-study.json)复算既有局部匹配位置：5对图像存在共230个成对计算的可见像素交集。局部匹配含JPEG误差，且尚未测得历史截图客户区边界，因此这不是最终官方点击坐标，不能据此宣称透明遮罩足以关闭布局重叠问题。本轮没有移动按钮或放宽布局约束。

验证结果：

- 34,084项CPU校验，含16,820个源PNG透明度像素比较、黑色块/选择子组合、逻辑边界、填充区、损坏数据和读取位置恢复；实际8组按钮四态透明轮廓一致。
- 合计128,367项遮罩及真实按钮检查，覆盖悬停、按下、禁用、隐藏/恢复、PassThrough、无效重绑、透明角穿透下层、单次点击分发及原HUD已有遮罩的回退恢复。
- 窗口集成150,644项检查，六分辨率共272,700个命令根坐标与独立BC1透明度结果比较，原聊天及原控件身份、场景生命周期、安装失败和解绑回退继续通过。
- Debug/Release构建、141项Python、70项素材基础、418项资源预检及288次GPU比较、803项HUD及812,688次合成GPU比较通过。
- 完整离线场景180项检查覆盖三次真实构造、17帧、7次Device.Reset、六分辨率及场景重入；使用合成角色/地图，不连接服务器。
